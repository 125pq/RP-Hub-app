## Package IDs

- Debug: `io.github.pq125.rphub`
- RC: `io.github.pq125.rphub.rc`
- Production: `io.github.pq125.rphub`

The RC is an Android `releaseCandidate` build type derived from `release`. It changes only the Android application ID suffix, version suffix, and label. RC and production use the same `dist`, Vue/runtime services, IndexedDB schema, Character and Novel pages, performance optimizations, and native plugins.

## Launcher audit

**BLOCKING RELEASE POLISH:** the current launcher/adaptive icon is still the default Capacitor/Android template artwork. The RC label correctly reads `RP Hub RC`, but a project-owned RP Hub icon is required before declaring final 0.1.0. No logo was designed in this commit.

## Known limitations

- Existing debug installs cannot update in place to production because the historical debug signing identity differs from the permanent release identity.
- No user-data migration between debug, RC, and production packages has been designed.
- Minor UX, gesture, layout, and interaction polish is deferred.
- Updater/self-update behavior is deferred.
- Full backup schema and migration policy are deferred; the current manifest still allows Android backup.
- Real file writing and real API requests were not executed in this RC task.
- Final APK should receive one manual same-signature RC update/install confirmation before final 0.1.0 promotion.
